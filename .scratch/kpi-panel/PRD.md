# 六週 KPI 面板：週曆條只亮必做、W1–W6 累計磚、CPAP 平均磚、連續兩週保險絲

Status: spec（票見 issues/01–05）
Source: docs/KPI面板-需求-20260911.md（2026-09-11）

## Problem Statement

Stanley 的計畫成不成立，定稿寫得很清楚：W1–W6 共 24 件必做完成 ≥20 才算成立，W7 回顧要看 CPAP 平均是否 ≥4h，連續兩週必做 <3 就要砍成 3 件並查睡眠與 CPAP。但頁面現在算不出這些數字，只能靠 AI 事後讀 log 才知道自己站在哪裡。

具體的落差：

- 週曆條把「當天任何動作有勾」都亮綠，平日 HIIT 套餐日勾了死蟲式也亮，看起來很勤勞，跟必做帳無關。
- Trend 頁只有「本週必做 n/4」，沒有跨週累計，看不到離 20 還差多少。
- CPAP 每天有填，但沒有平均，回顧時要自己翻表。
- 保險絲只看「當天睡眠差或 CPAP <4h」，不會偵測連續兩週掉隊。

## Solution

頁面自己把 KPI 算出來，四個地方各改一件事：

1. 週曆條只在「必做課表日且有打勾」的日子蓋勾，REST 日打勾不亮。
2. Trend 頁新增「W1–W6 必做 N/24（門檻 20）」磚，附出席率百分比，取代寫死的 /4。
3. Trend 頁新增「CPAP 平均 X.X h（門檻 4）」磚，W1 起、有填才算，達標與否標色。
4. 今日頁保險絲行多一種觸發：最近兩個完整週的必做各自 <3 → 顯示「砍成 3 件、查睡眠與 CPAP」提示。

四個門檻數字集中放常數，`node smoke_test.js` 全過即驗收。

## User Stories

1. As a 使用者，I want 週曆條只在必做課表日（LOW／UPP／SAT／SATGYM／SUN）有打勾時蓋勾，so that 一眼看到本週必做累積，不被 REST 日的打勾干擾。
2. As a 使用者，I want REST 日打勾後週曆條不亮綠，so that 平日 HIIT 套餐日不會誤算成必做出席。
3. As a 使用者，I want 週曆條的判定跟 weekDone 用同一套規則，so that 週曆條亮幾格就等於 Trend 磚的本週 n。
4. As a 使用者，I want 最低配打勾的日子在週曆條上也蓋勾，so that 我知道那天有出席，即使該週第二次最低配不計入必做數。
5. As a 使用者，I want Trend 頁有一塊「W1–W6 必做 N/24」磚，so that 我知道計畫成立的進度。
6. As a 使用者，I want 磚上標明門檻 20，so that 不用回頭翻定稿才知道及格線。
7. As a 使用者，I want 磚上附出席率百分比（N/24），so that 跟朋友或教練講進度時有一個數字。
8. As a 使用者，I want 累計只算 W1 到 W6 的必做，so that W0 前奏跟 W7 以後的紀錄不會混進 KPI。
9. As a 使用者，I want 累計沿用「最低配每 7 天只算 1 次」的規則，so that 每週的帳跟累計的帳一致。
10. As a 使用者，I want 累計沿用「REST 日打勾不算必做」的規則，so that 不會靠 HIIT 套餐灌水。
11. As a 使用者，I want 今天還在 W0 時磚顯示 0/24，so that 開跑前頁面不會壞掉或顯示奇怪的負數。
12. As a 使用者，I want 今天已過 W6 時磚仍顯示 W1–W6 的定格結果，so that W7 回顧時數字不會被 W7 之後的紀錄改動。
13. As a 使用者，I want 累計磚在 W1–W6 進行中就即時更新，so that 每週日送出資料後馬上看到進度。
14. As a 使用者，I want 原本的「本週必做 n/4」磚被累計磚取代或併入，so that Trend 頁不會多一塊重複資訊。
15. As a 使用者，I want Trend 頁有一塊「CPAP 平均 X.X h」磚，so that W7 回顧時直接看到有沒有達 4 小時。
16. As a 使用者，I want CPAP 平均只算有填 CPAP 時數的日子，so that 忘記填的日子不會被當成 0 拉低平均。
17. As a 使用者，I want CPAP 平均從 W1 開始算，so that W0 前奏的試戴資料不混進來。
18. As a 使用者，I want CPAP 平均一天都沒填時顯示「—」，so that 不會出現 NaN。
19. As a 使用者，I want CPAP 磚達標（≥4h）與未達標用不同顏色，so that 一眼看出狀態。
20. As a 使用者，I want CPAP 磚顯示到小數一位，so that 跟 7 天均重的格式一致。
21. As a 使用者，I want 保險絲在最近兩個完整週必做各自 <3 時觸發，so that 連續掉隊時系統主動叫我降載。
22. As a 使用者，I want 「完整週」指週一到週日都過完的週，so that 本週還沒過完不會在週一早上就誤觸發。
23. As a 使用者，I want 保險絲只從 W1（2026-09-14）起算、W0 不算，so that 開跑前的空白週不會觸發。
24. As a 使用者，I want 兩週各自 <3 才觸發、不是加總 <6，so that 一週 4 件一週 1 件（有特殊狀況）不會被誤判成連續掉隊。
25. As a 使用者，I want 今天在 W1 或 W2 時（還沒有兩個完整週）不觸發，so that 剛開跑不會被嚇到。
26. As a 使用者，I want 連續兩週保險絲觸發時今日頁出現「砍成 3 件、查睡眠與 CPAP」提示，so that 我知道該做什麼。
27. As a 使用者，I want 連續兩週保險絲跟原本的「當天睡眠差／CPAP <4h」保險絲各自獨立、可以同時顯示，so that 兩種警訊都不會被蓋掉。
28. As a 使用者，I want 連續兩週保險絲在 REST 日也顯示，so that 不用等到肌力日才看到（跟原本只在肌力日顯示的當天保險絲不同）。
29. As a 使用者，I want 在今日頁切換檢視日期時，連續兩週保險絲仍以今天為基準計算，so that 補登過去資料時提示不會亂跳。
30. As a 使用者，I want 24、20、3、4 這四個門檻數字放在同一處常數，so that 定稿改門檻時只改一個地方。
31. As a 使用者，I want localStorage 的 logs 與 cfg 結構完全不變，so that 手機上既有資料不用遷移。
32. As a 使用者，I want obsidian:// 送出格式與 CSV 表頭不變，so that Obsidian 日誌與搬家包不會壞。
33. As a 使用者，I want 頁面維持單檔、零外部依賴、零 build，so that 手機直接開 index.html 就能用。
34. As a 開發者，I want 一個「某週 MUST 完成數（含最低配扣抵）」的共用函式，so that 週曆條、本週磚、累計、保險絲四處用同一套帳。
35. As a 開發者，I want 一個「日期範圍取 logs」的共用函式，so that 累計與 CPAP 平均不各自重寫迴圈。
36. As a 開發者，I want weekDone 改成呼叫共用函式後行為不變，so that 現有 weekDone 測試照樣通過。
37. As a 開發者，I want 每一片（T1–T5）在 smoke_test.js 各有對應斷言，so that 任一片壞掉時 node smoke_test.js 會指出是哪一片。
38. As a 開發者，I want 現有測試一行都不刪改，so that 回歸保護不會被削弱。
39. As a 開發者，I want render 層的斷言用假 DOM 樁的輸出字串驗證，so that 不需要真的開瀏覽器。

## Implementation Decisions

**共用 helper（T1）**

- 新增「某週必做完成數」函式：輸入該週週一，回傳完成件數與最低配使用次數。規則與現行 weekDone 完全相同：課表鍵在 MUST 內、當天有任一動作打勾、最低配該週只有第一次計入。weekDone 改為直接呼叫它，回傳形狀不變。
- 新增「日期範圍取 logs」函式：輸入起訖日（含），回傳該範圍內有紀錄的 [日期, log] 序列，依日期排序。累計與 CPAP 平均都走它。
- 新增「某日是否計入必做」的判定，供週曆條與週函式共用，避免兩處各寫一次 MUST 判斷。判定不含最低配扣抵（扣抵是週層級的事）。

**門檻常數**

- 集中一個常數物件，四個值：必做總件數 24、成立門檻 20、連續掉隊門檻 3、CPAP 門檻 4 小時。另含 KPI 週範圍 W1–W6。所有顯示文字與判定都引用它，不散落字面數字。

**週曆條（T2）**

- did 判定改為「該日計入必做」，不再是「任何動作有勾」。REST 日即使打勾也不蓋勾、不顯示 ✓。
- 最低配日子照樣蓋勾（它有出席），不做週層級扣抵的視覺區分。
- 進度圓環不動，維持當天動作完成比例。

**W1–W6 累計磚（T3）**

- 以 cfg.start 為 W1 週一，逐週呼叫週函式，加總 W1 到 W6 共六週。今天在 W0 時六週全在未來，結果為 0。今天超過 W6 時結果定格。
- 磚文字格式：`N/24`，副標「W1–W6 必做（門檻 20）」，另一行出席率 `Math.round(N/24*100)%`。
- 取代現有 tWk 磚的內容與標籤。本週 n/4 併入副標或移除，不另開第四塊磚。

**CPAP 平均磚（T4）**

- 範圍：W1 週一到今天（含）。只取 log 有 CPAP 時數且為正數的日子。無資料顯示「—」。
- 顯示一位小數，副標「CPAP 平均 h（門檻 4）」。達標與否用既有 tile 的顏色機制標記，不引入新樣式系統。

**連續兩週保險絲（T5）**

- 判定基準日永遠是今天，不隨檢視日期改變。
- 取今天所在週之前的兩個週（週一到週日都已過完）。若任一週的週序 <1（即 W0 或更早）則不觸發。
- 兩週各自呼叫週函式，兩者完成數都 <3 才觸發。不是加總。
- 觸發時在今日頁保險絲行顯示「⚠️ 連續兩週必做 <3 → 砍成 3 件、查睡眠與 CPAP」。與現有當天保險絲獨立，兩者同時成立時兩句都顯示。不限肌力日，REST 日也顯示。

**不動的東西**

- localStorage schema、cfg.start、schedule()、MUST、obsidian:// 送出格式、csv() 表頭。
- 單檔、零依賴、零 build。

## Testing Decisions

**什麼是好測試**：只測外部行為。純函式測回傳值，render 函式測假 DOM 樁的 innerHTML 或 textContent 是否含預期字串。不測內部呼叫順序、不 mock 頁面自己的函式。

**唯一切面**：smoke_test.js。它把 index.html 的 script 與斷言 eval 進同一作用域，用假 DOM 樁接住輸出。新測試沿用這個機制，不新開檔案、不加框架。

**要測的模組與案例**

- 週函式：現有 weekDone 案例（2 最低配只算 1、REST 不算 → 3/4）必須原樣通過。
- 日期範圍函式：起訖含邊界、範圍外不取、無資料回空。
- 週曆條：塞一週資料含 REST 日打勾與 LOW 日打勾，render 後 wstrip 的 innerHTML 只有 LOW 那天含 did 與 ✓。
- 累計：塞 W1–W6 各週不同完成數（含最低配、REST 灌水），render 後累計磚 textContent 為預期 N/24 與百分比。另測今天在 W0 時為 0/24。
- CPAP 平均：塞 W0 有填、W1 部分填、部分空，平均只取 W1 有填的；全空顯示 —。
- 保險絲：塞「前兩個完整週都 2 件」觸發；「一週 4 一週 1」不觸發；「前一週在 W0」不觸發；本週進行中的資料不影響。斷言 wNote 的 textContent。
- 門檻常數：斷言四個值等於定稿數字，防止有人改磚文字時順手改數字。

**時間控制**：現有測試用真實 today，累計與保險絲依賴「今天是第幾週」。測試以塞 logs 的日期相對 cfg.start 建構，並在斷言時考慮 today 落在 W0 的情況（2026-09-11 執行時 wk=0）。若需固定 today，在 tests 字串內覆寫 today 相關變數後重呼叫 render，不改頁面程式。

**先例**：smoke_test.js 內的 weekDone 測試（塞 logs 後斷言回傳物件）與 sendToday 測試（呼叫後斷言 location.href 字串）。

## Out of Scope

- 進度圓環維持「當天動作完成比例」，不改成本週必做 N/4（2026-09-11 拍板）。
- 定稿 §9 第 2 項 RECOV 鍵：09-10 已拍板取消恢復週，程式為準，不做。
- StanleyInbox 的健身紀錄 log.md 舊表頭無 cpap 欄：非本 repo，另案。
- W7 之後的任何 KPI（喬山期出席、減量週追蹤）。
- 把 KPI 寫回 Obsidian 或 CSV 加欄位。
- 抽獨立 js 檔或引入測試框架。

## Further Notes

- 建議實作順序 T1 → T2 → T3 → T4 → T5，每片獨立可驗收，每片加測試後跑 `node smoke_test.js`。
- T3 與 T5 都依賴 T1 的週函式，T4 只依賴日期範圍函式。
- 今天（2026-09-11）仍在 W0，累計磚與保險絲在真機上會是 0/24 與不觸發，這是正確行為，不是 bug。
- 定稿出處：§7 W1–W6 列（24 件 ≥20）、§7 W7 列（CPAP 回顧）、§9 第 7 項（週曆條改以必做計）。
